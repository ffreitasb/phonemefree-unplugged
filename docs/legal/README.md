# Legal And Licensing

This directory explains how PhonemeFree Unplugged applies its dual-license model.

The short version:

- Hardware is open hardware under `CERN-OHL-S-2.0`.
- Firmware and software are copyleft software under `AGPL-3.0-or-later`.
- Third-party dependencies keep their own licenses.
- Project branding is not automatically licensed as a trademark.

The root policy lives in [../../LICENSE.md](../../LICENSE.md).

File-level SPDX notices override the directory default when they are more specific.

## SPDX Notices

Use concise SPDX headers for new project-authored files.

For firmware/software:

```text
SPDX-License-Identifier: AGPL-3.0-or-later
```

For hardware source:

```text
SPDX-License-Identifier: CERN-OHL-S-2.0
```

Do not replace third-party headers with project headers. Preserve upstream notices.

## Firmware Release Requirements

When distributing firmware binaries, release packages should include or clearly link to:

- The exact source code used to build the binary.
- `dependencies.lock` and the ESP-IDF version used for the build.
- Build and flash instructions.
- Partition table and web UI assets included in the image.
- Any local patches to third-party components.
- Installation information required to install modified firmware on the same class of device.

The project should not enable secure boot, flash encryption, signed-only updates, or other lock-in mechanisms in public hardware releases unless the corresponding installation information needed by recipients is also provided.

## Hardware Release Requirements

When distributing hardware design files or products based on this project, release packages should include or clearly link to:

- Complete preferred-form hardware source for modified PCB, schematic, and mechanical files.
- Manufacturing outputs derived from those sources, when products are manufactured from them.
- BoM and assembly notes sufficient for a recipient to understand the build.
- Notices required by `CERN-OHL-S-2.0`.

Commodity parts, modules, and development boards remain available components. Their own vendor documentation and licenses are not replaced by this project.

## Contributions

By contributing to a project-authored file, contributors agree that their contribution is provided under the license that applies to that file.

New files should follow the repository scope above. If a new file does not fit cleanly into that model, document the decision in the file header or in this directory before merging it.

## What Not To Do

- Do not move hardware source into firmware directories just to avoid the hardware license.
- Do not move firmware code into hardware directories just to avoid the software license.
- Do not import third-party code without preserving its notices.
- Do not publish binary-only firmware releases.
- Do not imply official endorsement for modified products through the `PhonemeFree` name or logo.

This document is project guidance, not legal advice.
